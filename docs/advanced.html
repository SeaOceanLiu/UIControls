5 进阶主题

本章深入引擎的四个高级方向：洛蒂动画引擎（描述 → 烘焙 → 播放）、多视口与多窗口（一进程多 UI 实例）、非可视化功能控件（热重载 / 数据绑定 / 布局解析 / 焦点管理 / 资源加载）、以及纯 C ABI 程序化构建。每节都附可直接运行的完整样例。

5.1 全面掌握洛蒂动画引擎

LuotiAni 是引擎内置的关键帧动画系统：JSON 描述动画 → prepare() 逐帧烘焙为离屏帧贴图 → 播放时按墙钟毫秒查表绘制。烘焙完成后 JSON 不再参与运行，运行时零插值零计算——这是它与逐帧实时求值的动画系统的本质区别。

5.1.1 动画描述文件（JSON）

官方资源 animations/rotateBtn/rotateBtn.jsonc（256×256 画布、60 帧的旋转按钮）是标准结构范本：

{
    "overview": {
        "version": "0.0.1",
        "name": "rotate button animation",
        "view": { "width": 256, "height": 256 },   // 画布尺寸：超出部分裁剪
        "frameRate": 60,                            // 不得为 0
        "totalFrames": 60,
        "loop": true                                // 必填（严格解析，缺失抛异常）
    },
    "layers": [
        {
            "name": "rotate button",
            "type": "image",                        // image / shape / text
            "src": "animations/rotateBtn/rotateBtn.svg",   // 资源包内路径
            "width": 256, "height": 256,            // 缺省则保持图片原始尺寸
            "opacity": 100,                         // 图层级默认不透明度（0~100）
            "blendMode": "blend",                   // normal/additive/modulate/blend/multiply
            "keyFrames": [
                { "frame": 0, "operation": [
                    { "type": "translate", "tx": 0, "ty": 0 },
                    { "type": "scale", "sx": 1, "sy": 1 },
                    { "type": "rotate", "angle": 0, "cx": 128, "cy": 128 },
                    { "type": "opacity", "opacity": 100 },
                    { "type": "visible", "visible": true }
                ]},
                { "frame": 59, "operation": [
                    { "type": "rotate", "angle": 360, "cx": 128, "cy": 128 }
                ]}
            ]
        }
    ]
}
操作类型字段语义
translatetx, ty相对上一关键帧增量累加
scalesx, sy相对上一关键帧累乘
rotateangle, cx, cy角度累加，绕 (cx, cy) 旋转中心
opacityopacity（0~100）百分比覆盖（内部转 0~255）
visiblevisible可见性覆盖
未列出的属性沿用上一关键帧的到达值；最后一个关键帧之后的帧保持到达值（carry-over）。第 0 帧关键帧必须存在（缺失直接抛异常）。

5.1.2 缓动与路径（easing / path）

easing 写在目标关键帧的操作上，对段内所有属性的插值统一做时间重映射；path 仅作用于 translate 的段内位置轨迹，控制点相对段起点。引擎级演示动画（test_luotiani 的 tl_demo）完整展示了两种能力：

                  "view": { "width": 256, "height": 256 },

        { "name": "layer1", "type": "image",
          "src": "animations/rotateBtn/rotateBtn.svg",
          "opacity": 100, "blendMode": "normal",

                { "type": "translate", "tx": 0, "ty": 0 },
                { "type": "rotate", "angle": 0, "cx": 128, "cy": 128 },
                { "type": "opacity", "opacity": 100 } ] },
            { "frame": 30, "operation": [

                  "easing": "ease-in-out",
                  "path": { "type": "bezier", "c1x": 80, "c1y": -120, "c2x": 200, "c2y": 150 } },
                { "type": "rotate", "angle": 180, "cx": 128, "cy": 128 },
                { "type": "opacity", "opacity": 100 } ] },
            { "frame": 60, "operation": [
                { "type": "translate", "tx": -120, "ty": -60, "easing": "ease-in-out" },

easing 值说明
linear（缺省）线性插值
ease-in / ease-out / ease-in-out三次缓入 / 缓出 / 缓入缓出
quad / sine / cubic二次 / 正弦 / 三次多项式曲线
cubic-bezier(x1,y1,x2,y2)自定义贝塞尔（x 须在 [0,1]）；未知值回退 linear
path 类型字段说明
bezierc1x/c1y（二次）、c2x/c2y（三次）控制点相对段起点
parabolavx, vy初速物理轨迹，重力由终点反解，t=1 精确到达终点
catmull-rompoints多点平滑过点曲线

5.1.3 C++ 完整用法

独立动画控件（Builder 链式，一步到位）：

auto ani = LuotiAniBuilder(BENCH)
    .loadAniDesc(string("animations/rotateBtn/rotateBtn.jsonc"))  // 资源根相对路径
    .setRect(SRect(20, 20, 256, 256))
    .prepare()                 // 逐帧烘焙（重复调用早退）
    .setAutoStart()            // 内部调 play()
    .build();
ani->create();
BENCH->addControl(ani);

引擎级加载 / 播放 / 调试接口（精细控制）：

auto ani = make_shared<LuotiAni>(BENCH);
ani->loadAniDesc(fs::path("animations/rotateBtn/rotateBtn.jsonc")); // 失败 throw（需 try/catch）
ani->prepare();               // 烘焙全部帧
ani->play();                  // 复位帧到 0 重播
// 播放控制
ani->pause();                 // 停住（保持当前帧）
ani->resume();                // 从暂停处继续（区别于 play 的重播语义）
ani->setFrame(30);            // 跳帧（未 prepare / 越界忽略）
ani->setLoop(false);          // 到尾帧触发 AnimationEnded 事件并停止
// 调试：读中间帧插值结果与烘焙画布
LuotiAni::OpData d = ani->getFrameOpData(0 /*layer*/, 7 /*frame*/);
float alpha = d.opacity;                        // 0~255 域
SharedSurface canvas = ani->getFrameCanvas(7);  // 该帧合成后的离屏画布
ani->draw(7, x, y, alpha);                      // 绘制指定帧（不推进播放）

挂载到按钮（按钮自带动画外观）：

auto rotateAni = LuotiAniBuilder(BENCH)
    .loadAniDesc(string("animations/rotateBtn/rotateBtn.jsonc"))
    .prepare().setAutoStart().build();
auto btn = ButtonBuilder(nullptr, SRect(530, 50, 120, 50))
    .setLuotiAni(rotateAni)
    .setTransparent(true)
    .setOnClick([](shared_ptr<Button> b) { /* ... */ })
    .build();
btn->create();
BENCH->addControl(btn);

5.1.5 机制细节与语义陷阱

  • 时间驱动：update() 用绝对墙钟毫秒推进帧（每帧毫秒 = 1000/frameRate），播放速度只与真实时间有关，与调用 update 的帧率无关（帧率低时一次跳多帧）；
  • 多实例共享烘焙：LuotiInstance(parent, shared_ptr<LuotiAni>, userId, ...) 共享同一份帧贴图，各实例独立推进；内存与 帧数×画布尺寸 成正比（60 帧 512×512 ≈ 63MB）；
  • 缩放校准：帧 Actor 非控件树成员，绘制当前帧前会校准缩放跟随父链（嵌套在 2x 缩放容器内动画也正确）；
  • play() 总是复位帧到 0 重播；C ABI playing 每次置 1 都是重播（无暂停/继续状态机，暂停/继续用 playing=0/1 近似）；
  • setFrame 跳帧后首次 update 不复位计时会连跳；animation 属性只写不读；未 prepare 时置 playing=1 被拒绝；
  • 图层类型 shape/text 解析支持但烘焙跳过（无可见输出）；AnimationEnded 事件已触发但尚无 C ABI 回调链路。

5.2 多视口与多窗口

UICornerstone 支持单进程多个 UI 实例：多实例 = 多个独立窗口（各自控件树 / 事件队列 / 焦点 / 数据上下文完全隔离）；多视口 = 一个窗口内划分多个子区域（共享后端，各自独立控件树）。

5.2.1 视图层次与能力位

UIInstance (owner，一个窗口)
├── ownsBackend = true；持有 Window / RenderDevice / InputBackend / TextRenderer
├── viewport = 整个窗口区域 (0,0,w,h)
├── bench（owner 自身控件根）
├── activeViewport：当前键盘焦点子视口（首个子视口创建时自动赋值；销毁时清 NULL）
└── children[]：CreateViewport 注册的子视口
    └── 每个子视口 = 一个 UIContext：
        ├── owner = 父；ownsBackend = false（共享后端）
        ├── viewport = 窗口坐标系的区域（渲染时 clip 到该区域）
        ├── bench / eventQueue / DataContext / FocusManager —— 每实例独立
        └── 注入队列 queuedEvents —— 每实例独立

后端能力决定多实例渲染策略，必须条件化：

uint32_t caps = UICornerstone_GetBackendCapabilities(g_inst);
if (caps & UICORN_BACKEND_CAP_MULTI_WINDOW)  { /* 非首个实例可真实开窗 */ }
if (caps & UICORN_BACKEND_CAP_RENDER_TARGET) { /* 可离屏渲染 */ }
能力位sdl3sfmlraylib
MULTI_WINDOW✓✓✗（单窗口架构）
RENDER_TARGET✓✓✓
CLIP_RECT✓✓✓
READBACK✓✓✓
raylib 为单窗口架构：多实例下仅首个实例有真实窗口，其余为 headless，对其渲染会串扰到主实例窗口。多窗口渲染前必须查能力位条件化。

5.2.2 单窗口多视口（C++ Binding）

一个 800×600 窗口划分两个子视口：左上 (0,0,400,300) + 右下 (400,300,400,300)，各自独立控件树，按钮点击弹窗显示本视口内容（sample_cpp_multiview 完整模式）：

auto ui = UICornerstone::Create(Config{}.WithBackend("sdl3").WithWindow("Multi-View Sample", 800, 600));

// 两个子视口（窗口坐标系下绝对区域）
auto vpA = ui->CreateViewport(0, 0, 400, 300);
auto vpB = ui->CreateViewport(400, 300, 400, 300);

// 每个子视口独立创建控件（句柄属于各自实例）
auto labelA = vpA->CreateLabel("Viewport A", 16.0f, 20, 12, 200, 28);
auto btnA   = vpA->CreateButton("Show Dialog", 20, 60, 160, 34);
btnA.SetCallback(PropertyNames::kEventClick, [&](const Event&) {
    vpA->CreateDialog("Hello from A", "", 0, 0, 280, 120);   // 弹窗在 vpA 内居中
});

// ── 主循环：子视口必须显式驱动 ──
while (!ui->IsQuitRequested()) {
    ui->ProcessEvents();      // 窗口输入轮询（按坐标路由到子视口）+ owner 注入队列
    vpA->ProcessEvents();     // 子视口各自消费自己的注入队列
    vpB->ProcessEvents();
    vpA->Update(dt);  vpB->Update(dt);
    ui->Clear();
    vpA->Render();            // 各自 clip 到自身视口区域
    vpB->Render();
    ui->Present();
}
ui->Shutdown();

事件路由要点：窗口输入按窗口绝对坐标路由到命中的子视口；未命中任何子视口 → owner 树；键盘事件先做 Ctrl+Tab 跨视口智能路由，再投递到活动视口。

5.2.3 多实例双窗口（C++ Binding）

两个独立窗口实例，跨实例通信通过普通 C++ 回调（控件句柄属于各自实例，不可混用）（sample_cpp_multiinstance 完整模式）：

auto uiA = UICornerstone::Create(
    Config{}.WithBackend("sdl3").WithWindow("Sample A", 640, 480));
auto uiB = UICornerstone::Create(
    Config{}.WithBackend("sdl3").WithWindow("Sample B", 640, 480));

auto labelA = uiA->CreateLabel("Window A (independent instance)", 18.0f, 20, 12, 420, 30);
auto editA  = uiA->CreateEditBox(20, 60, 380, 32);
auto btnA   = uiA->CreateButton("Send to B", 20, 110, 140, 36);
auto msgB   = uiB->CreateLabel("(no message)", 16.0f, 20, 110, 420, 30);

// A 窗口按钮 → 写 B 窗口的控件（跨实例）
btnA.SetCallback(PropertyNames::kEventClick, [&](const Event&) {
    msgB.SetString(PropertyNames::kCaption,
                   "Message: " + editA.GetString(PropertyNames::kTextContent));
});

// ── 主循环：全局事件泵 + 渲染条件化 ──
while (!uiA->IsQuitRequested() && !uiB->IsQuitRequested()) {
    int processed = 1;                 // 依次驱动每个实例，直到队列空
    while (processed > 0) {
        processed = (uiA->ProcessEvents() ? 1 : 0) + (uiB->ProcessEvents() ? 1 : 0);
    }
    uiA->Update(dt);  uiB->Update(dt);
    uiA->Clear(); uiA->Render(); uiA->Present();
    if (uiA->GetBackendCapabilities() & UICORN_BACKEND_CAP_MULTI_WINDOW) {
        uiB->Clear(); uiB->Render(); uiB->Present();   // raylib 下跳过
    }
}
uiA->Shutdown();  uiB->Shutdown();

5.2.4 C ABI 层

实例配置结构（可全 NULL/0 走默认）：

UIInstanceConfig cfg = { sizeof(UIInstanceConfig),   // 版本兼容检查必填
    "Secondary",        // debugLabel
    NULL,               // resourceRoot → 默认
    "第二窗口",          // windowTitle

UIInstance inst2 = UICornerstone_CreateInstanceFromPlugin("sdl3", &cfg);
// 或直接传后端回调表（静态链接路径）：
UIInstance inst1 = UICornerstone_CreateInstance(GetUIBackendCallbacks(), NULL);

// 子视口：在 owner 的窗口中划区域（仅 owner 可建，rect 为窗口坐标系）
UIInstance vp = UICornerstone_CreateViewport(inst1,
    (UIRect){ .x = 0, .y = 0, .w = 400, .h = 300 });
// 视口控制
UICornerstone_SetViewport(inst1, 0, 0, 400, 300);
float x,y,w,h;  UICornerstone_GetViewport(inst1, &x, &y, &w, &h);

调试辅助（_DEBUG 构建）：Debug_GetActiveViewport(inst) 查询活动子视口；Debug_IsControlFocused / Debug_IsControlHovered 断言焦点 / 悬停；Debug_SetMousePosition(inst, x, y) 注入鼠标坐标驱动 hover（无人值守测试用，Release 恒 0）。

5.2.5 隔离性保证

多实例 / 多视口的隔离是引擎设计保证（test_multi_instance_cabi 测试 1-5、test_multiviewport_cabi K1-K8 全覆盖）：

  • 事件隔离：同位置点击各自实例各自触发，事件不跨实例；
  • Action 隔离：两实例可注册同名 action，各绑各的控件；
  • 焦点隔离：每实例独立 FocusManager，多窗口可同时各有焦点环；FocusLost 清本实例 + 活动子视口焦点；
  • 悬停隔离：注入鼠标到 A 窗口不影响 B 窗口 hover；
  • 销毁安全：销毁活动视口 / 实例后 Debug 断言无悬垂引用（AliveCount 精确）；
  • Ctrl+Tab 跨视口规则：视口内存在可见焦点边界（WinFrame/Dialog）时优先视口内切换；全部隐藏才跨视口；Ctrl+Shift+Tab 反向。

5.3 非可视化控件（功能控件）

以下组件不直接显示，而是为控件树提供功能能力。它们大多挂在 UIContext 上（每 UI 实例一份）或在应用层手动创建。

5.3.1 HotReloader：布局文件热重载

开发期利器：监视布局 JSON 文件，保存后约 0.5 秒自动重建控件树。策略为完全重建（不保留输入框内容、悬停等控件状态）。

LayoutParser g_parser;
HotReloader g_reloader;
fs::path g_layoutPath;

// 重建回调（保存布局文件后自动执行）
void reloadLayout() {
    BENCH->removeAllControls();   // 1. 清除 Bench 所有子控件
    g_parser.clear();             // 2. 清 ID 映射（已注册 handlers 保留）
    auto root = g_parser.parseLayoutFile(g_layoutPath);  // 3. 重新解析
    if (!root) return;
    BENCH->addControl(root);      // 4. 重新挂根控件
    for (auto& bar : g_parser.getMenuBars())            // 5. 重新挂 MenuBar
        BENCH->addControl(bar);
}

// 初始化（实例创建后）
g_layoutPath = fs::path(Platform::GetBasePath()) / "layouts" / "test_layout_advanced.json";
g_reloader = HotReloader(g_layoutPath, reloadLayout);
g_reloader.setPollInterval(15);   // 每 15 帧检查一次（默认 30 ≈ 0.5s@60fps）

// 帧循环
void onUpdate() { g_reloader.poll(); BENCH->eventLoopEntry(); BENCH->update(); }
局限：轮询检测（非 OS 文件事件），延迟约 0.5 秒；只支持单文件监视；重建不保留控件状态。JSON 中 events 引用的 handler 在 clear() 后依然有效，新控件自动重新绑定。

5.3.2 DataContext：数据绑定

命名数据源存储 + 变更通知中心（每 UI 实例一份，UIContext::dataContext）。控件经 JSON bind 挂到 key 上，实现 data→UI 单向与 UI→data 双向同步。

class DataContext {
    void set(const string& key, const DataValue& value);   // 存储并通知所有 watcher
    DataValue get(const string& key) const;
    bool has(const string& key) const;
    void watch(const string& key, function<void(const DataValue&)> watcher);
    void unwatchAll();            // 布局热加载前自动调用
    void clear();
};
// DataValue 可承载 string / double / bool（isString/asString/asDouble/asBool）

C++ 侧手动读写：

auto ctx = g_uiInstance->dataContext;
ctx->set("sharedText", string("Hello from DataContext!"));
ctx->set("progressValue", 42.0);
double v = ctx->get("progressValue").asDouble();

// 布局 JSON 中绑定（mode: oneWay 缺省 / twoWay）
// "bind": { "text": { "source": "userName", "mode": "twoWay" },
//           "visible": "isEditable" }

可绑定属性：caption / text / placeholder / value / checkState / visible / enabled。双向绑定回写：EditBox text-changed → set(key, text)；CheckBox → 三态字符串；ScrollBar → 数值。watcher 用 weak_ptr 捕获控件，控件销毁自动失效。

5.3.3 LayoutParser：自定义事件处理器

JSON 布局的事件名是字符串，需要先 registerHandler 注册具名处理器，解析时按名匹配绑定：

void onSubmitClicked(shared_ptr<Control> c) { /* ... */ }

g_parser.registerHandler("onSubmitClick", onSubmitClicked);
g_parser.registerHandler("onIncProgress", [](shared_ptr<Control>) {
    auto ctx = g_uiInstance->dataContext;                 // 处理器内可访问数据上下文
    double v = ctx->get("progressValue").asDouble() + 10.0;
    if (v > 100) v = 0.0;
    ctx->set("progressValue", v);
});
auto root = g_parser.parseLayoutFile(g_layoutPath);      // 解析前必须注册完毕
BENCH->addControl(root);
{ "type": "button", "rect": { "x": 10, "y": 10, "w": 120, "h": 32 },
  "events": { "click": "onSubmitClick" } }   // 名字与 registerHandler 一致

机制：parseEvents() 按控件类型匹配事件 key（Button click、EditBox text-changed/enter 等），用 m_handlers.find(name) 查找到后包成控件回调；未注册的 handler 名静默跳过。C ABI 联动：UICornerstone_RegisterAction 注册的 action 会在 LoadLayout 时自动转为 parser handler。

5.3.4 FocusManager：焦点系统 API

每实例独立（UIContext::focusManager）。3.6 章节讲了行为，这里给出可编程接口：

focusManager->registerControl(ctl);    // 可聚焦控件自动注册（setFocusable(true)）
focusManager->focusNext(ctl);          // Tab 环下一项
focusManager->focusPrev(ctl);          // Shift+Tab 上一项
focusManager->registerBoundary(ctl);   // 焦点边界（Bench / WinFrame / ColorPicker）
focusManager->getVisibleBoundaryCount();  // 可见 boundary 数（Ctrl+Tab 跨视口路由依据）
focusManager->notifyControlFocused(ctl, true);   // byKeyboard=true 显示焦点环
focusManager->clearFocus();
focusManager->focusNextScope();        // Ctrl+Tab（跨 boundary）
focusManager->focusFirstInScope(scope);
鼠标点击聚焦时焦点环不显示（byKeyboard=false）；getVisibleBoundaryCount() 只统计 isVisible() 的边界——这正是 5.2.5 中"全部隐藏才跨视口"的实现依据。

5.3.5 ResourceProvider：统一资源加载

文件读取的统一入口（图片 / 字体 / 动画 / 布局文件都经它解析为字节流）：

// 工厂：文件系统实现（以 basePath 为根拼接路径，带内存缓存）
auto rp = ResourceProvider::createFilesystem(ConstDef::pathPrefix);
shared_ptr<vector<char>> data = rp->readFile("layouts/main.json");  // 读取 + 缓存
bool ok = rp->exists("assets/img/icon.png");

// C ABI 侧：实例创建时经 resourceRoot 指定根目录，NULL → 默认
// C++ Binding：Config.WithResourceRoot(path) / ResolveResource(relativePath)

分工：文件字节读取 = ResourceProvider；字体 = TextRenderer（loadFont / loadFontFromMemory）；纹理 = RenderDevice 后端回调（createTextureFromFile）。Label::loadFromResource、Actor::loadFromResource、LuotiAni 资源加载、LoadLayoutFromFile 均走此链。

5.4 直接使用 C ABI 接口程序化生成 UI

不用 JSON、不用 C++ 类，纯 C 程序化构建界面（工厂函数 + 属性系统 + 回调），完整工程可运行：

#include "UICornerstoneAPI.h"

static UIInstance g_inst;

static void onBtnClick(UIControlHandle ctl, const UIEventData* ev, void* user) {
    UIControlHandle status = UICornerstone_FindControl(g_inst, "status");
    if (status) UICornerstone_SetString(g_inst, status, "caption", "Clicked!");
}

static void onCheck(UIControlHandle ctl, const UIEventData* ev, void* user) {
    // 事件负载：union 按事件类型取对应字段
    int state = ev->data.intVal;                    // check-changed → 新状态
    // selection-changed → ev->data.selection.idx/.val
    // color-changed     → ev->data.color.r/g/b/a
    // text-changed      → ev->data.strVal
    // value-changed     → ev->data.doubleVal / floatVal
}

int main(void) {
    g_inst = UICornerstone_CreateInstanceFromPlugin("sdl3", NULL);
    if (!g_inst) return 1;
    UICornerstone_SetViewport(g_inst, 0, 0, 800, 480);

    // ── 程序化创建控件树：容器 + 子控件 ──
    UIControlHandle panel = UICornerstone_CreatePanel(g_inst, 20, 20, 360, 220);
    UIControlHandle btn   = UICornerstone_CreateButton(g_inst, "Click Me", 30, 30, 140, 36);
    UIControlHandle cb    = UICornerstone_CreateCheckBox(g_inst, "Enable", 30, 80, 24, 24);
    UIControlHandle lbl   = UICornerstone_CreateLabel(g_inst, "Idle", 16.0f, 30, 130, 200, 28);
    UICornerstone_AddChildControl(g_inst, panel, btn);   // 挂树
    UICornerstone_AddChildControl(g_inst, panel, cb);

    UICornerstone_SetString(g_inst, lbl, "id", "status");   // 属性系统 + FindControl 检索
    UICornerstone_SetCallback(g_inst, btn, "click", onBtnClick, NULL);
    UICornerstone_SetCallback(g_inst, cb, "check-changed", onCheck, NULL);

    // ── 菜单三件套程序化组装 ──
    UIControlHandle file = UICornerstone_CreateMenuPanel(g_inst);
    UIControlHandle open = UICornerstone_CreateMenuItem(g_inst, "Open", 0);
    UICornerstone_MenuPanelAddItem(g_inst, file, open);
    UICornerstone_MenuPanelAddSeparator(g_inst, file);
    UIControlHandle bar = UICornerstone_CreateMenuBar(g_inst, 0, 0, 800, 26);
    UICornerstone_MenuBarAddMenu(g_inst, bar, "File", file);

    // ── 主循环（六步顺序不可颠倒）──
    while (!UICornerstone_IsQuitRequested(g_inst)) {
        UICornerstone_ProcessEvents(g_inst);
        UICornerstone_Update(g_inst, 1.0 / 60.0);
        UICornerstone_Clear(g_inst);
        UICornerstone_Render(g_inst);
        UICornerstone_Present(g_inst);
    }
    UICornerstone_DestroyInstance(g_inst);
    return 0;
}
JSON 布局其实走的是同一条属性系统：LoadLayout 内部创建 LayoutParser 并把 RegisterAction 注册的 action 自动转为 parser handler。程序化与声明式可混用——先 LoadLayout 建骨架，再 FindControl 细化操作。

C ABI 完整函数速查见 9.3 C ABI 速查表；UIEventData 事件负载结构见 9.3 与各控件回调节。
